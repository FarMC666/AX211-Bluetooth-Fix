## 下一步与停止条件

优先在同一构建的命令选择和初始化错误处理之间核对内部选择字节的来源、能力缓存从 0x1002 应答更新的位置及其值，以及 628 如何传到初始化失败回调。判据是同一初始化实例选中 0xf4、缓存中第 41 字节相应位为零、支持检查直接返回 628、同一错误传到失败回调。若有一环不符，追踪实际最先进入失败回调的操作。若证实全部条件，再评估调用层按真实能力选择并正确解析 V1 的可行性。当前证据不足以部署修复。运行时取证如需调试权限或重启，应先提供采集差异、时序影响和恢复办法，由用户确认。

## V1 的原生回调与可观察的下一步

在 24H232 的初始化表中，+0x9e4500 指向命令选择函数 +0x144c13，下一项指向 +0x144cd4。V1 分支同时选择内部命令 0xa3（0x2002）及 initCmdReadLeBufferSizeCB（+0x1462a5）。回调在状态为零时读取 16 位 LE ACL 长度和 8 位包数，检查两者是否同时为零或同时非零，写入缓冲区状态。两者都为零时仍可继续，因此验收不能要求两个值非零。V2 有独立回调和额外的 ISO 字段。

V1 回调即使收到非零状态，也会跳过字段写入并向初始化序列传入零。因此，看到下一步只能证明序列推进。应同时取得 0x2002 的成功 Command Complete、状态后的三个参数字节，以及下一步证据。序列下一项在 LE 条件成立时尝试 0x202f（LE Read Maximum Data Length）；若提交即返回 628，也可继续推进，该情况下应用下一项日志或后续 HCI 事务作证。历史抓包尚无 0x2002 应答，缓冲区实际值待真机确认。
